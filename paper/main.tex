\begin{abstract}
Long-running agents accumulate facts that change, expire, and must sometimes be
deleted. Answering \emph{what was true then} and \emph{what did the agent know
then} requires distinguishing valid time from transaction time, and honouring
deletion across every store a query can reach. Recent systems advertise exactly
these capabilities: temporal graphs expose validity fields, memory stores record
update history, and recent work formalises bitemporal operators for agent
memory. We ask whether those features deliver the semantics they name.

We build a deterministic lifecycle generator whose ground truth is computed by
an oracle cross-checked against an independent SQLite implementation, render the
same histories into natural language, and replay them into five widely-used
open-source systems---Mem0 \citep{mem0}, LangMem, Graphiti
\citep{graphiti,zep}, Cognee and Hindsight \citep{hindsight}---under
forward-checkpoint transaction-time replay, so an \texttt{as-of} query is
answered from a store holding only what was known by then.

Two designs emerge over 20 matched conditions. \emph{Consolidating} stores
replace a superseded value: Mem0 and LangMem answer transaction-scoped current
queries well ($0.952$, $0.890$) but historical valid-time poorly ($0.364$,
$0.323$), because the prior value no longer exists. \emph{Retaining} stores keep
it and fail to filter: read at the retrieval layer, Graphiti, Cognee and
Hindsight score $0.196$, $0.207$ and $0.194$ overall with valid-time $0.000$,
$0.015$ and $0.000$ over 195 cases each --- three independent implementations
failing almost identically. The deficit is also budget-dependent in a way prior
evaluations would miss: at a one-item budget Graphiti matches Mem0 on valid
time, and separates only as the budget grows.

Reading the retained history with an LLM shows the information was there all
along, but does not reliably exploit it: over the same stores, Cognee's reader
answers 192 of 195 valid-time cases while Hindsight's answers 67 --- below a
consolidating store that discarded the history. Retention decides whether
correctness is \emph{recoverable}; it does not make recovery automatic.
Deletion separates the same way. Both systems' deletion APIs clear their
retrieval-reachable stores, but deletion requested in prose is silently ignored
--- the operationally relevant case for an assistant asked to forget something.
Finally, cost is write-dominated and the split is a design choice: ingest
averages $4.7$\,s against $0.3$\,s for query in one system, and the inverse in
another that defers graph construction to read time.

We claim no novelty for bitemporal modelling \citep{snodgrass1985,toki},
deterministic supersession \citep{memstrata}, or forgetting evaluation
\citep{forgeteval,memoryagentbench}. The contribution is measurement, and the
finding that a system can expose temporal fields, and even filter on them,
without answering temporal queries correctly.
\end{abstract}

\section{Introduction}

An agent that remembers must also revise, expire, and forget. Two questions
recur: \emph{what was true at time $t$} (valid time) and \emph{what did the
system know at time $t$} (transaction time). Current-state stores conflate them,
and deletion is harder still---a value removed from a serving index may survive
in a history table, a vector store, or a raw episode log, ready to resurface.

These needs are recognised. Graphiti attaches creation, validity, invalidity and
expiry timestamps to graph edges; Mem0 records add/update/delete history beside
a mutable vector store; Hindsight combines invalidation archives, histories,
audit logs and derived-record cleanup; and recent work makes the temporal model
explicit, from a graph-native bitemporal store to a bitemporal operator algebra
and a bi-temporal ledger with deterministic supersession.

Given that, the open question is not \emph{whether to model time} but
\textbf{whether the modelling produces correct answers under the operations
agents actually perform}. We answer it by measurement:

\begin{enumerate}
  \item a deterministic lifecycle generator with independently computed ground
        truth, cross-checked by a second oracle implementation;
  \item a natural-language rendering of those histories so opaque systems can be
        scored against the same truth;
  \item forward-checkpoint transaction-time replay, so an \texttt{as-of} query is
        answered from a store that has seen only what was known by then;
  \item a residual scan that asks where a purged payload physically survives,
        under a prose deletion request and under each system's deletion API.
\end{enumerate}

\paragraph{Contributions.}
(i) An identical-history comparison of five deployed memory systems, separating
consolidating from retaining designs; each side of the taxonomy is confirmed on
implementations held out from its construction.
(ii) A separation of \emph{information loss} from \emph{missing filtering},
obtained by reading two systems' stores both at the retrieval layer and through
an LLM, which also shows that a reader repairs the gap in one system and not the
other.
(iii) A cross-store deletion-completeness measurement under both a prose
instruction and each system's native API, which the closest prior systems
describe as a feature but do not measure.
(iv) Measured write/read cost and latency, and a reproducible sealed harness
whose every reported number recomputes offline from per-case transcripts,
including preserved negative results and four retracted measurements.

\section{Related Work}

\paragraph{Temporal modelling is prior art.}
A \citep{graphnativebitemporal} graph-native bitemporal memory store keeps valid- and transaction-time
intervals with point-in-time retrieval, and TOKI \citep{toki} defines bitemporal operators
over a dual-row schema with released code. MemStrata \citep{memstrata} pairs a bi-temporal ledger
with a deterministic (subject, relation, object) supersession rule and reports
stale-fact rate as its headline metric. We therefore claim none of these.

\paragraph{Forgetting evaluation is prior art.}
ForgetEval \citep{forgeteval} generates seeded lifecycle cases with deterministic substring scoring
across supersession, decay, amnesia, purge and drift; MemoryAgentBench \citep{memoryagentbench} evaluates
selective forgetting among four competencies. Springdrift \citep{springdrift} already combines
append-only memory, auditability and git-backed recovery, which retires any
``first git-native auditable memory'' framing.

\paragraph{Deployed systems and security.}
Mem0 \citep{mem0}, Zep/Graphiti \citep{zep,graphiti}, MemGPT/Letta \citep{memgpt},
HippoRAG~2 \citep{hipporag2} and Hindsight \citep{hindsight} form the baseline landscape. MINJA \citep{minja} shows query-only poisoning; MemLineage \citep{memlineage}
proposes lineage-based action gating; A-MemGuard \citep{amemguard} and MemIncept
\citep{memincept} are current defence and adaptive-attack baselines.

\paragraph{What is left.}
No prior work we found measures, under one controlled history, both bitemporal
answer correctness \emph{and} where deleted content physically survives across a
system's derived stores. Our literature review is single-reviewer with a
deterministic 10\% rescreen; searches, exclusions and rescreens are logged and
frozen with the artifact.

\section{Design}

Raw events are immutable and interpretations derived; valid time is distinct
from transaction time; current truth is a view over history; retrieval is scoped
before ranking; every derived memory cites evidence; untrusted content is data,
never policy; indexes are rebuildable from the ledger.

\begin{itemize}
  \item \textbf{Event ledger.} Typed events (\texttt{ingest}, \texttt{reconfirm},
        \texttt{supersede}, \texttt{expire}, \texttt{purge}), append-only, over
        JSONL or a git transaction adapter.
  \item \textbf{Bitemporal oracle.} A fold over events produces beliefs; an
        independent SQLite implementation serves purely as a correctness
        cross-check, not an operational baseline.
  \item \textbf{Disposable projections.} Exact, lexical, hashing-vector,
        learned-vector and graph indexes rebuilt from materialised beliefs;
        reciprocal rank fusion, then validity, authority and poisoning gates.
  \item \textbf{Deletion.} Purge tombstones with receipts, plus an
        encrypted-payload profile whose per-belief key destruction is verified
        after a git clone.
  \item \textbf{Provenance gate.} Signed, tenant-scoped ingestion quarantine
        separating write acceptance from sensitive-action activation.
\end{itemize}

\section{Which fragment of bitemporal semantics does each system implement?}
\label{sec:fragment}

The query we need is standard \citep{snodgrass1985}: for subject $s$ and
attribute $a$, return the value valid at event time $V$ according to what the
store had recorded by transaction time $T$. Answering it requires six
capabilities, and the systems differ less in whether they \emph{have} temporal
metadata than in what can be \emph{predicated} on it. We therefore classify
support into five levels, which turn out to explain every measurement in
\S\ref{sec:results}:

\begin{description}
  \item[\textsc{absent}] the information is not stored;
  \item[\textsc{prose}] stored, but only inside free text, so no predicate can
        filter on it;
  \item[\textsc{off}] a queryable field exists and a filter is available, but is
        not applied by the default retrieval path;
  \item[\textsc{mismatch}] a queryable field exists and is applied, but denotes a
        different timeline than the query requires;
  \item[\textsc{yes}] representable, queryable, and applied.
\end{description}

not what documentation claims.}
\label{tab:fragment}
\small

\toprule

\midrule
C1 valid-time interval    & \textsc{yes} & \textsc{absent} & \textsc{prose} & \textsc{yes} \\
C2 transaction time       & \textsc{yes} & \textsc{absent} & \textsc{absent} & \textsc{mismatch} \\

\bottomrule
\end{tabular}

Three entries in Table~\ref{tab:fragment} carry most of the explanatory weight.

\textbf{C2 \textsc{mismatch} is an expressiveness limit, not a bug.} Graphiti
stores \texttt{created\_at} and \texttt{expired\_at}, which look like a
transaction-time axis. They record \emph{wall-clock ingestion}: in our runs they
carry 2026 timestamps for a history whose modelled transaction times lie in
2025. No predicate over them can express ``as of what was known on
2025-02-18''. This is why we enforce the transaction-time axis structurally, by
forward-checkpoint replay, rather than by asking any system to filter on it ---
and why C5 is \textsc{absent} rather than \textsc{off}.

\textbf{C1 \textsc{prose} is the distinction a capability checklist misses.}
LangMem does retain validity information --- its stored memories contain strings
such as ``valid from January 3, 2025''. But the store holds opaque values under
a namespace, so validity is legible to a reader and invisible to a query
planner. A survey that asked ``does the system record when a fact became true''
would score LangMem as supporting valid time; no predicate can use it.

\textbf{C3 separates closing an interval from overwriting a row.} Mem0 and
LangMem consolidate: a superseding fact replaces its predecessor, so the prior
value is destroyed rather than bounded. Graphiti closes intervals by setting
\texttt{invalid\_at}, but does so unreliably --- absent on 26 of 80 superseded
edges and internally contradictory ($\texttt{invalid\_at} \le
\texttt{valid\_at}$) on 4 of 54 dated invalidations. C3 is therefore the axis on
which the two design families separate, and \S\ref{sec:results} measures the
consequence: consolidating stores lose history outright, while Graphiti retains
it and fails to filter it.

The reader should note where the causal chain terminates. C2 and C1 are
data-model properties. C3's unreliability in Graphiti is not: it is a property of
the LLM extraction step that populates the store, and it does not improve with a
stronger extractor (\S\ref{sec:results}). For LLM-backed temporal stores the
extraction layer, not the schema, is the binding constraint --- which is a
statement about the pipeline that fills a temporal database, and the reason a
schema-level capability audit would mis-rank every system in
Table~\ref{tab:fragment}. That table covers the three systems whose stores we
inspected directly; Cognee and Hindsight enter in \S\ref{sec:reader} and are
characterised by measured behaviour rather than by schema inspection.

\section{Experimental Setup}\label{sec:setup}

\paragraph{Workload.} A seeded generator emits typed histories over
entity/attribute state machines with configurable reconfirm, expire and purge
probabilities. Query truth is computed by the oracle independently of retrieval.

\paragraph{Rendering.} Histories are rendered to dated conversational turns.
The generator's synthetic tokens (\texttt{entity-000}, \texttt{place-38})
collapse under a semantic embedder, leaving systems unable to tell entities
apart, so an injective relabelling maps them to distinct natural names. The
relabelling preserves oracle semantics exactly and doubled Mem0's measured exact
accuracy, isolating tokenisation from temporal semantics.

\paragraph{Replay.} Transaction time is monotonic, so turns are ingested in
recorded order and every query is answered at the checkpoint matching its
transaction time. This costs $O(\text{turns})$ per cell and, unlike single-pass
ingestion, actually tests whether a store can answer as of a past point.

\paragraph{Scoring.} Deterministic. Let $E$ be the expected values at the queried
$(\text{valid time}, \text{transaction time})$ and $S$ the superseded values for
the same subject/attribute. A response is \emph{exact} iff every $e \in E$ occurs
in the returned text and no $s \in S$ does; when $E = \emptyset$ (the fact was
purged or expired) exactness requires that no $s \in S$ occurs, i.e. correct
abstention. Evidence recall is $|E \cap \text{returned}| / |E|$, and stale-use is
the fraction of returned values drawn from $S$. \textbf{Because exactness
quantifies over the whole returned set, it is a function of the retrieval budget
$k$}; we set $k{=}5$ throughout and report a sweep over $k$ in
Figure~\ref{fig:budget}. Rates are case-weighted with Wilson 95\% intervals, and
abstention is computed only over cells that contain abstention cases.

\paragraph{The oracle defines ground truth.} Expected values are computed by the
oracle, so an oracle "system" scores $1.0$ by construction; it is not an
empirical result. We report it only as a scale anchor, and its agreement with the
independent SQLite implementation is a differential-testing check on our own two
implementations of one specification, not external validation.

\paragraph{Systems.} Internal baselines (append-only, full/recent context, BM25,
last-write-wins) and the oracle; external systems Mem0 \texttt{0.1.118} and
Graphiti \texttt{0.29.2} on Neo4j~5.26, both with \texttt{gpt-4o-mini} at
temperature~0 and \texttt{text-embedding-3-small}. Runs are sealed with
canonical config, environment, source hash and per-file checksums.

\textbf{Two systems consolidate; one retains without filtering.} LangMem was
added precisely because a typology drawn from the same two systems it describes
is not evidence. It lands in the Mem0 class on every axis --- exact $0.576$,
recall $0.647$, stale-use $0.343$, high \texttt{transaction\_as\_of} ($0.890$)
against low \texttt{valid\_time} ($0.323$), and budget-stability ($0.595 \to
0.576$) --- despite an independent implementation and no database server. It is
not uniformly weaker: it handles expiry better than either ($0.438$ against
$0.125$ and $0.000$), so the consolidation signature is specific rather than
general weakness.

\textbf{Mem0 consolidates.} It is strong on transaction-scoped current queries
($0.956$) and much weaker on historical valid time ($0.374$). Of its non-exact
cases, 84\% return a stale value with the expected value \emph{absent} --- a
genuine loss of history rather than a ranking artifact --- and this is stable
across retrieval budgets (Figure~\ref{fig:budget}).

\textbf{Graphiti retains but does not filter.} It reaches $0.944$ evidence
recall and places an edge about the queried subject at rank~1 in 99.4\% of
cases, yet scores $0.194$ exact, because it returns superseded revisions
alongside the current one. \textbf{This deficit is budget-dependent, and we
report it as such}: our scorer requires every expected value and no superseded
value across the returned set, so a system that returns $k$ facts about a
one-attribute subject is penalised for its own retained history. At $k{=}1$ the
two systems' valid-time accuracy is \emph{identical} ($0.385$); as $k$ grows
Graphiti collapses to $0.000$ while Mem0 is nearly flat
(Figure~\ref{fig:budget}). We therefore do not claim Graphiti cannot represent
valid time. The defensible claim is narrower and does not depend on $k$: its
retrieval does not apply the validity metadata it stores, so downstream filtering
is left to the caller.

\textbf{Two fairness objections, tested.} Earlier runs disabled Graphiti's BM25
channel --- a workaround for a bug in an embedded backend we did not use --- and
ran Mem0 against a shared history database that its own library corrupts under
contention. We re-ran both under corrected configurations. Neither changed the
result: Graphiti under its shipped hybrid retrieval scores $0.196$ against
$0.194$ cosine-only with valid-time $0.000$ either way, and Mem0 with an
isolated database scores $0.603$ against $0.612$. These reruns also provide our
only same-protocol replication, and it is instructive: Mem0's expiry accuracy
moved $0.000 \to 0.125$ (2 of 16 cases) between runs, exactly the instability its
Wilson interval predicts. We therefore draw no conclusion from either system's
expiry number.

\textbf{Does Graphiti's own filter repair it?} Enabling its native valid-time
\texttt{SearchFilter} raises exact from $0.224$ to $0.318$ and cuts stale-use
from $0.561$ to $0.360$, but collapses evidence recall from $0.873$ to $0.318$:
precision is bought by discarding evidence, and valid-time remains $0.093$.
Two structural limits cap it. First, extracted \texttt{invalid\_at} is absent on
26 of 80 superseded edges and internally contradictory
($\texttt{invalid\_at} \le \texttt{valid\_at}$) on 4 of 54 dated invalidations,
so stale edges satisfy the filter indefinitely. Second,
\texttt{created\_at}/\texttt{expired\_at} record wall-clock ingestion rather than
the history's transaction time, so no \texttt{as-of} bound is expressible. This
ceiling is not an extraction-quality artifact: with \texttt{gpt-4o} in place of
\texttt{gpt-4o-mini} on four matched cells, valid-time is unchanged
($0.111 \to 0.111$) and expiry stays $0.000$, though \texttt{transaction\_as\_of}
improves ($0.514 \to 0.625$) and purge degrades ($0.296 \to 0.176$); with two
seeds these movements are within noise and we draw no conclusion from them.

\subsection{Deletion: the API works, the instruction does not}

Our first attempt at this measurement was unfair in two ways, and correcting it
reversed the conclusion. It gave our substrate a typed \texttt{purge} operation
while giving the deployed systems an English sentence, and that sentence
restated the value it asked to delete --- so any system storing its input
verbatim was penalised by construction. We now run two conditions with a
non-restating instruction (Figure~\ref{fig:residual}).

\begin{figure}[t]
\centering
\includegraphics[width=\linewidth]{figures/residual.pdf}
\caption{Where a purged payload survives, split by whether a query path can
reach the store. Counts are substring occurrences over differently shaped stores
and are not comparable in magnitude across systems; the reachability split is
the claim.}
\label{fig:residual}
\end{figure}

Under a \textbf{natural-language instruction}, residual occurrences of the
purged value are the reference implementation 3 (audit ledger only), Mem0 15 (exposed memories 3,
vector store 3, history 9), Graphiti 18 (edges 3, entity nodes 9, episodes 6).
Under each system's \textbf{native deletion API} (\texttt{Memory.delete},
\texttt{remove\_episode}) the picture changes completely: Mem0 falls to 12 with
\emph{zero} in exposed memories and \emph{zero} in the vector store, and
Graphiti falls to 3 with \emph{zero} in edges and episodes.

Two conclusions follow, and the first contradicts what we previously reported.
\textbf{Both systems' deletion APIs do clear their retrieval-reachable stores};
purged content does not linger in the serving path when deletion is actually
invoked. What fails is \textbf{deletion expressed in prose}: told in natural
language to delete a fact, neither system acts on it, and the value remains
retrievable. For agents that receive deletion requests conversationally --- the
normal case for a user asking an assistant to forget something --- that gap is
the operationally relevant one.

Two residues survive API deletion. Mem0's SQLite history retains 12 occurrences
and in fact \emph{grows}, because deletion appends history rows; Graphiti's
LLM-generated entity summaries retain 3, which \texttt{remove\_episode} does not
rewrite. Mem0's history and our own append-only ledger are the same class of
store --- an audit log no query path reads --- so we do not claim our substrate
is uniquely clean. Counts are substring occurrences over differently shaped
stores and are not comparable in magnitude; the reachability split is the claim.
This rests on a single seeded history (12 events, three purged values) and one
backbone, with extraction that is not bit-reproducible.

\subsection{Retrieval channels}

A hard fixture isolates one necessary channel per category. A learned dense
channel resolves held-out synonyms at recall@1 $1.0$ where the dependency-free
hashing channel scores $0.0$, quantifying that channel's alias-table-only
design. Calibrated fusion gave no held-out gain over fixed reciprocal rank
fusion, and state-level decay did not dominate rank-level decay.

Cognee \textsc{graph-completion} & \textbf{0.930} & \textbf{0.985} \scriptsize{(192/195)} & \textbf{0.622} \\
\bottomrule
\end{tabular}
\end{table}

\textbf{The retrieval layer fails uniformly.} Three independently built
retaining systems land within noise of each other --- Graphiti $0.196$, Cognee
$0.207$, Hindsight $0.194$ overall, with valid-time $0.000$, $0.015$ and $0.000$
over 195 cases each. Retaining history but not filtering it is therefore a
property of the design class, not of one implementation.

\textbf{The reader layer does not.} Read by an LLM over the same graph, Cognee
answers 192 of 195 valid-time cases and all 228 transaction-scoped ones,
distinguishing ``as of 2025-01-03'' from ``as of 2025-01-31'' for one subject.
Hindsight's reader, over its own retained store, reaches only $0.344$ --- below
Mem0's $0.364$, a store that has thrown the history away. So the information is
present in every retaining system, and a reader \emph{can} exploit it, but
attaching an LLM does not reliably do so: recovery varies by nearly a factor of
three between two systems that both retain. Transaction time is the exception
that proves the mechanism: it is perfect for Cognee by construction, because
forward-checkpoint replay leaves only what was known in the store.

That distinction does not rescue the consolidating systems. Mem0 ($0.364$) and
LangMem ($0.323$) sit in the middle whichever way they are read, because a
superseding write destroys its predecessor: there is nothing for a reader to
recover. \textbf{Retention decides whether correctness is
recoverable at all; it does not make recovery automatic.} Retrieval-layer
filtering is broken in every retaining system we measured, and whether a reader
repairs it is a property of that reader's context and prompting rather than of
retention alone. A deployment on a consolidating store cannot be made correct
without changing the store; a deployment on a retaining store can be, but only
if the read path is built to use what the store kept.

The reader configurations differ from the rest in whether an LLM synthesises the
answer, so they are an upper bound on what a reader can recover
rather than a like-for-like win over the other columns, all of which are scored
at the retrieval layer. Expiry remains low for every configuration
($0.125$ at best over 16 cases), so we draw no conclusion there.

Ingest is roughly $16\times$ slower than query, and embeddings account for
0.2\% of spend: essentially all cost is the extraction and consolidation the
write path performs. At these rates an ingested turn costs about
\$0.0005. The practical consequence is that consolidating designs pay their
price on every write, in exchange for the current-state accuracy
\S\ref{sec:results} measures --- and that a store which retains history without
filtering it, like Graphiti, is not cheaper at read time either, since its cost
is also incurred on write.

The write/read split is a design choice, not a constant. Cognee inverts it:
\texttt{add} only stages text and averages $0.76$\,s, while its query path
averages $7.93$\,s because the graph build runs at the first query of each
checkpoint ($5.00$\,s under \textsc{chunks}, so roughly $3$\,s of the remainder
is the reader LLM). Mem0 pays at write, Cognee at read, for comparable work. We
measure cost only for the in-process systems: Cognee and LangMem run in separate
interpreters, so their token usage falls outside our instrumentation and is not
reported.

We report accuracy on this sweep only as a sanity check and do not compare it
with Table~\ref{tab:external}: it is the first multi-attribute configuration
(three attributes per entity, each drawn from a different semantic class) and
therefore a different workload. Exact accuracy moved $0.610 \to 0.527 \to 0.539$
as entities grew $2 \to 4 \to 8$, which is not monotone and rests on three seeds
per scale.

\subsection{External validity}\label{sec:external}

On human-written LongMemEval conversations \citep{longmemeval}, retrieval
quality tracks how much temporal or cross-session reasoning a question demands:
mean gold-token recall was knowledge-update $0.724$, single-session-user
$0.622$, preference $0.314$, multi-session $0.287$, temporal-reasoning $0.221$,
single-session-assistant $0.151$ (10 instances per type).

We flag three limits that keep this a pilot rather than a result. First, scoring
is deterministic substring/token presence over retrieved memories and is
deliberately \emph{not} the benchmark's LLM-judged QA metric, so these numbers
are incomparable to any published figure. Second, the ranking is sensitive to
protocol: LongMemEval's official retrieval scoring excludes no-evidence
abstention instances, and excluding them here reorders the top two types
(single-session-user $0.810$ above knowledge-update $0.794$). Third, gold answers
range from 1 to 46 scoreable tokens across types, and several temporal-reasoning
golds are computed quantities carrying rubric text, which caps attainable recall
on those instances --- so the cross-type gap is partly a property of the answer
format, not only of retrieval difficulty. A distractor-laden run on the harder
split was attempted but is \textbf{retracted}: it compared three instances
against a ten-instance mean, and on matched instances the effect disappears
(temporal-reasoning in fact rises, $0.125 \to 0.167$).

Separately, Mem0 silently dropped memory \texttt{UPDATE}/\texttt{DELETE} actions
during ingestion --- 15 across these 60 conversations, and 23 across 6
conversations of the longer split --- which we traced to an unvalidated
positional-id lookup swallowed by a broad exception handler while
\texttt{add()} reports success. Dropped updates leave superseded values in
place, so Mem0's scores here are conservative.

\subsection{Provenance security}

Signed, tenant-scoped gating admitted $3/4$ attacks as inert data while
activating $0/4$, with benign utility preserved---but it fails once a trusted
signer is compromised: provenance proves origin, not signer honesty. This is a
mechanism study; GPU-bound defences were out of scope.

\section{Negative Results and Corrections}

We preserve results that did not go our way: state-level decay did not beat
rank-level decay, fusion calibration gave no held-out gain, signed provenance
failed under signer compromise, and an early channel ablation saturated at $1.0$
and had to be redesigned.

Two measurements were \textbf{retracted rather than quietly fixed}. Graphiti
cell group ids repeated across runs while the Neo4j reset did not wipe the
group, so later runs queried graphs still holding earlier episodes (36 per cell
where one run produces 12); the affected filtered and extractor runs are marked
invalid and were re-run under verified isolation. A first purge scan reported
Mem0 at zero residual because it read Graphiti's raw database but only Mem0's
API-exposed memories; the corrected scan adds Mem0's vector store and history
database with a per-run database path.

\section{Reproducibility}

Runs are sealed with canonical config, environment, source-tree hash and
per-file checksums, and verified by an aggregate checker. The frozen synthetic
fixture is byte-reproducible and split-disjoint. Tests and lint pass on CPython
3.11. Third-party datasets are used locally and never redistributed.

\section*{Limitations}

Histories are synthetic with hand-specified operation
profiles; contradiction density is approximated by operation mix and revision
count. Two external systems, one backbone, and LLM extraction that is not
bit-reproducible. The literature review is single-reviewer. Purge claims cover
declared stores and tested failure points, not backups, OS caches or
provider-side copies.

Three further limits bound every number above. Histories are synthetic with
hand-specified operation profiles, so contradiction density is approximated by
operation mix and revision count rather than sampled from real usage. All runs
use a single backbone (\texttt{gpt-4o-mini}) with LLM extraction that is not
bit-reproducible; our one same-protocol replication moved a small-denominator
category by 0.125, which is why we draw no conclusion from expiry. And the
deletion result rests on a single seeded history, so it establishes a direction,
not a rate.

\section*{Ethics Statement}

This work evaluates three open-source memory libraries on fully synthetic
histories and on a public benchmark, and reports defects we found in them. We
report an implementation defect in one system that causes silent loss of memory
updates; because it biases that system's measured scores downward, our reported
numbers are conservative rather than unfairly harsh, and we state this in the
text. No user data was collected. The public benchmark is used locally under its
own terms and is not redistributed; its licence status is unresolved, which we
disclose rather than assume. No human subjects participated: a protocol for a
human audit study is released with the artifact but was not run, and we make no
human-effectiveness claim. Finally, the deletion result has a user-facing
consequence we want stated plainly --- an assistant asked in conversation to
forget something may not do so --- which is a privacy risk for deployments that
treat conversational deletion requests as effective.

\section*{Future Work}

Whether provenance-linked diffs actually help human
auditors is the largest untested claim. A preregisterable protocol, a seeded
planted-fault generator, a crossover assignment and a deterministic scorer are
included in the artifact, but no participants were recruited, so we make no
human-effectiveness claim. Running it requires ethics review or a documented
exemption, a pilot for variance, and an a priori power analysis.
