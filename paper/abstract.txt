Long-running agents accumulate facts that change, expire, and must sometimes be deleted. Answering what was true then and what did the agent know then requires distinguishing valid time from transaction time, and honouring deletion across every store a query can reach. Recent systems advertise exactly these capabilities: temporal graphs expose validity fields, memory stores record update history, and recent work formalises bitemporal operators for agent memory. We ask whether those features deliver the semantics they name.

We build a deterministic lifecycle generator whose ground truth is computed by an oracle cross-checked against an independent SQLite implementation, render the same histories into natural language, and replay them into five widely-used open-source systems—Mem0, LangMem, Graphiti, Cognee and Hindsight —under forward-checkpoint transaction-time replay, so an as-of query is answered from a store holding only what was known by then.

Two designs emerge over 20 matched conditions. Consolidating stores replace a superseded value: Mem0 and LangMem answer transaction-scoped current queries well (0.952, 0.890) but historical valid-time poorly (0.364, 0.323), because the prior value no longer exists. Retaining stores keep it and fail to filter: read at the retrieval layer, Graphiti, Cognee and Hindsight score 0.196, 0.207 and 0.194 overall with valid-time 0.000, 0.015 and 0.000 over 195 cases each — three independent implementations failing almost identically. The deficit is also budget-dependent in a way prior evaluations would miss: at a one-item budget Graphiti matches Mem0 on valid time, and separates only as the budget grows.

Reading the retained history with an LLM shows the information was there all along, but does not reliably exploit it: over the same stores, Cognee's reader answers 192 of 195 valid-time cases while Hindsight's answers 67 — below a consolidating store that discarded the history. Retention decides whether correctness is recoverable; it does not make recovery automatic. Deletion separates the same way. Both systems' deletion APIs clear their retrieval-reachable stores, but deletion requested in prose is silently ignored — the operationally relevant case for an assistant asked to forget something. Finally, cost is write-dominated and the split is a design choice: ingest averages 4.7 s against 0.3 s for query in one system, and the inverse in another that defers graph construction to read time.

We claim no novelty for bitemporal modelling, deterministic supersession, or forgetting evaluation. The contribution is measurement, and the finding that a system can expose temporal fields, and even filter on them, without answering temporal queries correctly.
